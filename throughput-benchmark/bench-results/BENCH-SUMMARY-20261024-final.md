## Caveats

- One run per suite: differences of a few percent are within run-to-run noise.
- Both Flink writers ran side by side on the same nodepool and bucket, so each rate is under the same shared load.
- Paimon's Iceberg export(Paimon\_as\_iceberg) is on (`ICEBERG_COMPAT=true`): every Paimon commit also writes Iceberg metadata, work with downstream Iceberg readers.
- The snapshot test ran on compacted tables (section above), the hot test on uncompacted ones; snapshot numbers are not comparable with sessions that did not compact.
- Query times compare engines on equal CPU and memory (StarRocks 3 BEs × 9 cpu / 38 Gi vs DuckDB 27 cpu / 114 Gi; memory limit is 90% of the pod memory and cache memory is 20% of it); **DuckDB's cache_httpfs uses 256 KiB blocks, the same as StarRocks' datacache_block_size** .
- Linux page cache sits outside both engines' cache settings and is not equal: In this benchmark session, a StarRocks BE held ~26 GiB of page cache, DuckDB only held ~3-4.5 GiB, so StarRocks' cached passes could re-read from RAM where DuckDB's read its cache disk.
